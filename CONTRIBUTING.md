# Contributing

Thank you for helping improve Easy Ads Integration Validator. Contributions should keep the tool focused on static inspection of Unity AppLovin MAX and LevelPlay mediation projects.

## Before Opening A Change

- Search existing issues and pull requests for related work.
- For substantial changes, open an issue first so the intended behavior can be discussed.
- Keep changes focused and avoid unrelated formatting or dependency updates.
- Do not include credentials, private project data, generated binaries, or proprietary SDK files.

## Pull Requests

Describe the user-facing problem, the approach, and any compatibility or scope implications. Include focused tests or validation for behavior changes, and update public documentation when commands, reports, supported profiles, or limitations change.

Before submitting, run the narrowest relevant checks locally and report the exact commands and results in the pull request. Do not claim runtime, dashboard, emulator, device, or generated-build validation from this static tool.

## Reporting A Problem

Use the bug-report form for reproducible defects and include the tool version, operating system, target framework, command shape, redacted output, and the smallest project evidence that demonstrates the issue. Use the feature-request form for proposed behavior changes.

All contributors are expected to follow the [Code of Conduct](CODE_OF_CONDUCT.md). Security concerns belong in [SECURITY.md](SECURITY.md), not in a public issue.
